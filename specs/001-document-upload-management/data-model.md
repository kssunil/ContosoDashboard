# Data Model: Document Upload and Management

## Document

Represents the current metadata and storage location for one uploaded file.

| Field | Type/constraint | Rules |
|---|---|---|
| DocumentId | integer, primary key | Generated by the database; required |
| Title | string, required, max 255 | Must not be empty or whitespace |
| Description | string, optional, max 2000 | Optional user-provided explanation |
| Category | string, required, max 100 | Must be one of the six predefined category values |
| FilePath | string, required, max 500 | Relative storage path only; generated by the system |
| OriginalFileName | string, required, max 255 | Display/download name; never used as a filesystem path |
| FileSize | integer/long, required | Must be greater than zero and no more than 25 MB |
| MimeType | string, required, max 255 | Captured from validated file metadata |
| UploaderId | integer, required, foreign key to User | Set from the authenticated user, never from client input |
| ProjectId | integer, optional, foreign key to Project | Null for personal documents |
| TaskId | integer, optional, foreign key to TaskItem | If set, must belong to the selected project |
| UploadedDate | UTC datetime, required | Set by the service |
| UpdatedDate | UTC datetime, required | Updated on metadata/file replacement |
| IsDeleted | boolean, required | Soft state for metadata/audit consistency; storage removal is permanent after confirmation |

Predefined category values are: `Project Documents`, `Team Resources`, `Personal Files`, `Reports`, `Presentations`, and `Other`.

## DocumentTag

Represents one normalized custom tag assigned to a document.

- `DocumentTagId`: integer primary key.
- `DocumentId`: required foreign key to Document.
- `Tag`: required text value with a bounded maximum length.
- Enforce duplicate prevention per document after normalization.

## DocumentShare

Represents explicit sharing beyond the default owner/project-member visibility.

- `DocumentShareId`: integer primary key.
- `DocumentId`: required foreign key to Document.
- `UserId`: optional foreign key to User for individual sharing.
- `TeamId`: optional future/team identifier if team sharing is implemented in the training scope.
- `SharedByUserId`: required foreign key to User.
- `SharedDate`: UTC datetime set by the service.
- A share must target a user or supported team, not neither; duplicate active shares are rejected.
- A recipient who is not a project member must not gain access to a project document unless the explicit share policy permits it; the implementation must apply one consistent rule in service authorization and tests.

## DocumentVersion

Represents a prior or current file revision when a document is replaced.

- `DocumentVersionId`: integer primary key.
- `DocumentId`: required foreign key to Document.
- `VersionNumber`: positive integer unique per document.
- `FilePath`, `OriginalFileName`, `FileSize`, and `MimeType`: values for that revision.
- `UploadedByUserId`: required foreign key to User.
- `UploadedDate`: UTC datetime.
- The active Document points to the current version; prior versions remain available for audit/history according to access rules.

## DocumentActivity

Represents an auditable document action.

- `DocumentActivityId`: integer primary key.
- `DocumentId`: required foreign key to Document.
- `ActorUserId`: required foreign key to User.
- `Action`: required text value: Upload, Download, Preview, MetadataEdit, Replacement, Share, Delete, or ScanRejected.
- `OccurredDate`: UTC datetime.
- `Details`: optional bounded text for safe, non-sensitive context.

## Relationships

- User 1-to-many Document through UploaderId.
- Project 1-to-many Document; Project 0-to-many Document for personal files.
- TaskItem 1-to-many Document; TaskItem association is optional.
- Document 1-to-many DocumentTag, DocumentShare, DocumentVersion, and DocumentActivity.
- User 1-to-many DocumentShare as recipient and sharer.
- Existing User, Project, TaskItem, and Notification rows remain the source of identity, project membership, task context, and in-app alerts.

## Authorization Rules

- An authenticated employee can view/download their personal documents.
- A project member can view/download documents associated with that project by default.
- An explicit share can grant access to a recipient according to the approved sharing rule.
- The owner can edit metadata, replace, share, and delete their document.
- A project manager can upload and delete documents associated with their project.
- An administrator can view, download, edit, share, and delete any document.
- Every list, search, preview, download, edit, replace, share, and delete query must apply these rules before returning or mutating data.

## Upload State Transition

1. `Selected`: browser has one or more candidate files.
2. `Validated`: title/category, extension, MIME type, size, and local safety result pass.
3. `Stored`: generated relative path is written to local storage.
4. `Persisted`: Document and related metadata are committed.
5. `Available`: authorized list/search/project views expose the document.
6. `Rejected`: validation or authorization fails; no document row is committed.
7. `CleanupRequired`: storage succeeded but metadata persistence failed; the service removes the newly written file and reports failure.

## Deletion State Transition

1. `Active` -> `DeleteConfirmed` after the authorized user confirms.
2. `DeleteConfirmed` -> `Deleted` after storage removal, metadata update, and activity logging succeed.
3. If storage removal fails, retain the metadata state needed for retry and record the failure; do not claim successful permanent deletion.
